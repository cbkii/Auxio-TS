# TS18 Device Profile Overview

- Target device: TS18/Topway `s9863a1h10_Natv` / `s9863a1h10`.
- Runtime: Android 10 / SDK 29.
- Display: 1280x720 landscape.
- Insets: top status bar around 55px; right navigation bar around 55px.
- Stock `com.tw.music` exists as a system priv-app at `/system/priv-app/com.tw.music_a41e/com.tw.music_a41e.apk`.
- Stock `com.tw.music` appears integrated with system/vendor configuration and UID/system behaviour.
- DoFun Variety `com.dofun.variety` launcher/theme is installed.
- Diagnostics were captured from TermOne as a normal app UID, approximately `u0_a177`, under `u:r:untrusted_app`, not ADB shell/root.
- `adbd` is running for USB gadget state, `mtp,adb`, but no TCP/local ADB listener was observed.
- USB/OTG ADB is physically unavailable in the user setup.
- `/storage/usbdisk0` exists and is required for runtime music-library validation.
- DoFun evidence supports fixed entries `com.tw.music/com.tw.music.MusicActivity` and `com.tw.media/com.tw.music.MusicActivity`.

### Stock `com.tw.music` implications

`com.tw.music` is present as a system priv-app. A normal user-signed Auxio-TS APK with package ID `com.tw.music` cannot be assumed to install over it.

Expected install outcomes on this exact device:

| Condition                                                                           | Expected outcome                                                                    |
| ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Stock `com.tw.music` still installed and no matching signature                      | `topwayTwMusicRelease` install/update likely fails with package/signature conflict. |
| Stock `com.tw.music` disabled/uninstalled for user 0 through ADB shell/Shizuku/root | `topwayTwMusicRelease` may become installable depending on package-manager state.   |
| Root/system-image replacement                                                       | Exact package replacement possible if performed deliberately and reversibly.        |
| Normal app shell only                                                               | Cannot remove/disable stock `com.tw.music`; can only collect limited diagnostics.   |

## Package-manager/dump limitations observed

From the normal app shell, commands like `pm dump`, `dumpsys package`, and appops access for `com.tw.music` were denied with permission errors such as missing `android.permission.PACKAGE_USAGE_STATS` or cross-user privileges.

Treat TermOne/Termux-only validation as a limited diagnostic lane, not as proof that package-manager operations will work.

## Direct repo implications

1. `topwayTwMusicRelease` is still the exact DoFun `com.tw.music` replacement target, but it is not guaranteed installable on this stock system without privileged package management.
2. Add a `com.tw.media` alternate DoFun-entry variant, but document it as stock-conflict-aware and mainly useful for users with root/Shizuku/ADB/system package control. Do not represent it as a universal no-root bypass.
3. Runtime validation docs must separate normal app-only diagnostics from ADB shell, Shizuku, and root lanes.
4. Overlay code must be Android 10 safe and 1280x720/right-nav/top-status-bar aware.
5. Storage validation must include `/storage/usbdisk0` and Android 10 storage permission behaviour.
6. Private/system UID parity remains evidence-only unless a later approved design PR proves a safe protocol and rollback path.
