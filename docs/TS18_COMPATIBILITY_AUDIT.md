# TS18 Compatibility Audit — 2026-06 Hardening Pass

This audit records the repo-wide TS18/Topway/DoFun compatibility scan performed after the redacted `s9863a1h10` Android 10 device-profile seed. It classifies implementation surfaces without claiming real TS18 runtime success.

## Runtime crash-risk hardening — 2026-06 release-readiness pass

A second pass focused on process-level crash/ANR risk (not just compatibility identity). Findings and the fixes applied:

| Risk                            | Evidence confidence                  | Finding                                                                                                                                                                                                                                                                                                                                          | Fix                                                                                                                                                                                                                                                                                                                        | Regression guard                                                                                                                                                                                                 |
| ------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native metadata library load    | Inferred (release-APK ABI dependent) | `TagLibJNI` called `System.loadLibrary("tagJNI")` in an `object` initializer. A missing/mismatched `.so` for the device ABI raises `UnsatisfiedLinkError` wrapped in `ExceptionInInitializerError`. Because these are `Error`s, they bypass `MusicRepository.index()`'s `catch (e: Exception)` and crash the process on the first metadata read. | Load attempt moved into a guarded `isAvailable` flag; the call site (`openNative`) is also wrapped to catch a call-time `UnsatisfiedLinkError`. Each affected file degrades to `MetadataResult.ProviderFailed` → `InvalidSong` (skipped), so the scan completes with a usable/empty library plus a single diagnostic line. | `musikr` `TagLibJNIAvailabilityTest` (init does not throw; `open` returns `ProviderFailed`).                                                                                                                     |
| Release native-method stripping | Inferred (release/minify only)       | The JNI-bearing `TagLibJNI` class had no R8 `-keep` rule, unlike its `NativeInputStream`/`Metadata` siblings. R8 could rename/strip it in a minified release build, producing a release-only native-bind failure.                                                                                                                                | Added `-keep class org.oxycblt.musikr.metadata.TagLibJNI { *; }` to both `musikr/proguard-rules.pro` and `musikr/consumer-rules.pro`.                                                                                                                                                                                      | New `scripts/check-native-keep-rules.sh`: fails if any class declaring `external fun` lacks a keep rule, or if the duplicated consumer/proguard rule sets drift. Wired into the `lint.yml` head-unit-safety job. |
| Startup shortcut registration   | Inferred (OEM launcher dependent)    | `Auxio.onCreate` called `ShortcutManagerCompat.setDynamicShortcuts(...)` unguarded. A partial/buggy `ShortcutManager` on an OEM head-unit launcher (e.g. DoFun) could throw and crash every launch before the UI exists.                                                                                                                         | Wrapped in `try/catch` with a `Timber.w` diagnostic; dynamic shortcuts are a non-essential convenience and must never block startup.                                                                                                                                                                                       | Covered by compile/lint; behaviour mirrors the adjacent Topway visibility-hook guard.                                                                                                                            |

These are safe, layered fallbacks: the primary path is unchanged when the native library and launcher behave normally, and each failure now produces a diagnostic plus a usable degraded state instead of a process crash.

### Deferred — requires physical TS18 evidence

- Whether the shipped release APK actually contains a `.so` matching the TS18 ABI (`arm64-v8a` vs `armeabi-v7a`) must be confirmed by inspecting a CI-built release APK (`zipinfo`/`aapt`) and/or installing on the device. The fixes above prevent a crash if it is missing, but do not by themselves guarantee metadata extraction works on-device.
