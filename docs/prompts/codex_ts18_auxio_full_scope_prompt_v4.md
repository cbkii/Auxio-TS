## Non-negotiable constraints

- Android 10/API 29 runtime is the compatibility target.
- Preserve standard Auxio behaviour.
- Gate TS18/DoFun/Topway behaviour to topwayCompat / variant-specific code unless there is a clear standards-based fix.
- Root/Magisk does not provide platform signing, UID 1000, signature permissions, vendor identity, SELinux domain, or Topway private authority.
- Do not fake TWUtil/Cardoor/private vendor binders.
- Do not copy smali wholesale into production. Use stock/VLC as evidence, then implement maintainable Kotlin/Java equivalents.
- Do not delete/disable stock packages from app code.
- Do not add framework hooks/LSPosed/Magisk-only runtime dependencies to the normal APK.
- Do not write `/system`/`vendor`/partitions directly. Optional Magisk work must be systemless and reversible.

## Task 2 — Fix observed `LocationObserver` invalid-provider crash

Observed crash in TS18 Auxio-TS v5.0.6 capture:

```text
java.lang.SecurityException: Failed to find provider  for user 0; expected to find a valid ContentProvider for this authority
  at android.content.ContentResolver.registerContentObserver(...)
  at org.oxycblt.musikr.fs.track.LocationObserver.<init>(...)
```

Required fix:

- Audit `LocationObserver`, track/artwork fetchers, Coil model/fetcher code, SAF/file/content URI conversion, and observer registration.
- Never register a content observer for URI with null/blank authority or unsupported scheme.
- Only register content observers for resolvable `content://` authorities.
- Do not register observers for raw paths, `file://`, DirectFS roots, empty URI, or malformed source values.
- Catch and downgrade `SecurityException`, `IllegalArgumentException`, and provider-not-found runtime failures.
- Preserve valid artwork/source loading.
- Add tests for blank authority, empty string, cancelled picker, `file://`, `/storage/usbdiskN`, missing provider, stale tree URI, valid media provider URI.

Acceptance:

- A bad or stale source cannot crash `com.tw.music`.
- UI, overlay, MediaSession, cached now-playing, and repairable source state remain available.

## Task 5 — Immediate cached now-playing fast resume

Playback resume from Floating Controls / DoFun / widget must not wait for full library scan when a valid cached track exists.

Use VLC and stock evidence:

- VLC `onPlay()` and media-button play call `loadLastAudio()` when there is no current media.
- Stock widget/service publish title/artist/progress from service state and routes commands directly to service/presenter.

Implement a small versioned `FastResumeSnapshot` or equivalent containing:

- stable URI/path;
- source mode;
- title/artist/album/duration;
- position/progression;
- queue/index snapshot if feasible;
- timestamp/revision;
- access/permission state.

Startup/command flow:

1. attach service/session immediately;
2. publish cached metadata/playback state quickly;
3. prepare cached media directly if accessible;
4. start playback if requested;
5. continue full library load in background;
6. reconcile transient item with real library item once loaded.

Add tests for valid direct path, valid content URI, missing USB, revoked SAF, no saved state, and later library reconciliation.

## Task 6 — Stock `com.tw.music` and VLC integration surfaces

Do not analyse Spotify further except as negative control.

Use `GH_TOKEN`/`GITHUB_TOKEN` to inspect `cbkii/t-music`. Important evidence:

- stock manifest: `com.tw.music`, `android.uid.system`, API 29, `MusicActivity` singleTask, `MusicService`, `MusicWidgetProvider`;
- stock `MusicService` registers and handles `com.tw.music.action.cmd/.prev/.next/.pp`;
- stock service returns sticky restart semantics;
- widget sends sticky `cmd=update` and explicit service `PendingIntent`s;
- widget uses title, artist, progress, duration, bounded album art;
- shim docs define maintainable MediaSession/notification bridge points.

Use public VLC as positive Android-standard evidence:

- `PlaybackService` is `MediaBrowserServiceCompat`;
- `MediaSessionCompat` has media-button receiver, flags for media buttons and transport controls, active session;
- `onPlay`/media button can load last audio;
- metadata includes title/artist/album/duration/display fields/album art URI;
- playback state exposes actions, queue item, repeat/shuffle, extras;
- VLC sends `com.android.music.metachanged` legacy broadcast.

Implement safe equivalents in Auxio-TS:

- topwayCompat-only stock command surfaces for `.cmd`, `.prev`, `.next`, `.pp`, `cmd=update`, `appWidgetIds`;
- explicit service routing for `com.tw.music.MusicService` alias if it exists, delegating to canonical Auxio playback state;
- robust `MediaSessionCompat` active early with media-button flags/actions;
- consider/verify `MediaBrowserServiceCompat` identity under the variant package;
- legacy `com.android.music.metachanged` broadcast, topwayCompat-only by default, with VLC-compatible extras;
- bounded widget/notification art;
- no private vendor APIs.
