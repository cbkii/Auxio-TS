# Bounded HOME Play

The canonical session advertises `org.oxycblt.auxio.action.HOME_PLAY_V1` in initial, empty and playable states. Clients send `protocol=1` and a future `deadline_elapsed_ms` on the device's elapsedRealtime clock, no more than 5000 ms ahead of receipt (`HOME_PLAY_MAX_WINDOW_MS`). A request with another protocol value, a deadline already passed, or one further ahead than that is rejected.

The receiver rejects invalid/expired requests. Deferred queue/raw restoration retains the deadline and has no detached ShuffleAll fallback. An expired or passive restore cannot be promoted by launch-autoplay preferences. The restored player remains paused until decoder STATE_READY; a one-use deadline gate then admits playback only inside the original window. A later explicit Pause/Play or seek, replacement restore, cancellation or holder release invalidates the pending gate. During an active restore, another bounded HOME Play joins its intent instead of arming an independent gate. The bounded request never dispatches its fallback as an unbounded ShuffleAll; a previously owed unbounded request remains independent. A bounded request that arrives while an unbounded Play is already owed (boot or launch autoplay, a media key, the app's own button) joins that Play and its fallback: the deadline can drop only its own request, never an earlier one that carried none. Timeout in the client is not an acknowledgement or cancellation; the source's own gate supplies the playback-commit bound.

Normal warm Play remains available. One player, queue, session, notification and focus authority are preserved. A timely playback commit is not a hard real-time guarantee about the first audible hardware sample; TS18 audibility and audio handover remain physical acceptance items.

Tests cover arbiter expiry/fallback/cancellation, explicit seek, decoder readiness before/at expiry, one-use admission, replacement and stale expiry, plus a focus-admission test seam where acquiring focus crosses the deadline and any newly acquired focus is released. The launcher companion also tests actual action delivery against an API29 cross-process fixture; that fixture is not this application's complete restore engine.
